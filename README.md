# In-Memory Vector Database

An educational, high-performance in-memory vector database built from scratch in C++. This project demonstrates how core Data Structures & Algorithms (DSA) and Database Management System (DBMS) principles are applied to high-dimensional AI embeddings (such as those generated by LLMs). 

The repository implements and benchmarks two vector search methodologies: a **brute-force k-NN linear scan** and a **greedy graph-based approximate nearest neighbor (ANN) search**.

---

## Key Features

* **In-Memory Storage model:** Native `std::vector` implementation storing high-dimensional vectors in volatile RAM, completely bypassing slow disk I/O bottlenecks.
* **Optimized Distance Engine:** Custom implementations of distance metrics designed for high throughput:
  * **Cosine Similarity:** Measures the angle between vectors (contextual direction, crucial for text embeddings).
  * **Squared Euclidean Distance:** Avoids expensive square root (`sqrt`) and power (`pow`) CPU operations to dramatically speed up calculations during large-scale scans.
* **Algorithmic Search Paradigms:**
  * **Brute-Force Linear Scan (k-NN):** A baseline search that scans the entire database to find the absolute nearest neighbor with 100% recall.
  * **Greedy Graph Search (ANN):** Constructs a single-layered proximity graph where each vector is connected to its $M$ nearest neighbors ($M=16$). Search is conducted via greedy hill-climbing traversal starting from a seed node.
* **Benchmarking & Analysis Tools:** Comparison scripts to directly compare accuracy, search latency, and graph build/indexing overhead (the "Write Penalty").

---

## Mathematical Foundations

### 1. Cosine Similarity
LLM embeddings care primarily about the angle (semantic direction) rather than the magnitude of vectors:

$$\text{Similarity}(A, B) = \frac{A \cdot B}{\|A\| \|B\|} = \frac{\sum_{i=1}^d A_i B_i}{\sqrt{\sum_{i=1}^d A_i^2} \sqrt{\sum_{i=1}^d B_i^2}}$$

### 2. Squared Euclidean Distance
Used for Euclidean distance comparisons. By omitting the square root calculation, we save significant CPU cycles:

$$d^2(A, B) = \sum_{i=1}^d (A_i - B_i)^2$$

## Performance Benchmarks

Below are actual execution benchmarks run on a machine compiling with GCC 12 (`g++ -std=c++17 -O3`).

### 1. Linear Scan Scale Test (1,000,000 Vectors)
Tested with **1 Million random vectors** (128 dimensions each):
* **Memory Footprint:** ~500 MB RAM
* **Search Latency (Squared Euclidean):** **110.58 ms**
* **Conclusion:** While 110 ms is fast, linear search ($O(N \cdot d)$) does not scale to production databases containing billions of vectors. An indexing strategy is required.

### 2. Algorithmic Comparison (10,000 Vectors, 128 Dimensions)
Comparing brute-force linear search vs. greedy graph approximate search:

| Metric | Brute-Force Linear Search | Greedy Graph Search (Approximate) |
| :--- | :--- | :--- |
| **Search Time Complexity** | $O(N \cdot d)$ | $O(\log N \cdot d)$ (average) / $O(N \cdot d)$ (worst-case) |
| **Insertion Time Complexity** | $O(1)$ | $O(N \cdot d)$ |
| **Graph Construction Overhead** | N/A | **12,170.1 ms** (due to $O(N^2 \cdot d)$ upfront pairwise calculations) |
| **Search Latency (1 Query)** | **1.96 ms** | **0.15 ms** |
| **Accuracy / Recall** | **100%** (Index 3751, Distance 7.40) | **Approximate** (Index 969, Distance 8.20) |
| **Search Speedup** | Baseline (1x) | **~13.15x faster** |

> [!WARNING]
> **The Write Penalty:** While graph search yields a **~13x speedup** during query time, building the graph takes **~12.17 seconds** for just 10,000 vectors. This illustrates the trade-off between offline index construction latency and online query execution speed.

## Quick Start

### Prerequisites & Dependencies

* **C++ Compiler:** A C++ compiler supporting C++17 or higher (e.g., `g++` via MSYS2 MinGW-w64 on Windows).
* **Python Runtime:** Python 3.x and the `requests` library (for running API simulation tests).
* **C++ Libraries (Header-only, included in root):**
  * **[cpp-httplib](https://github.com/yhirose/cpp-httplib):** A lightweight C++11 header-only HTTP server/client library.
  * **[nlohmann/json](https://github.com/nlohmann/json):** A modern C++ header-only JSON library.

### Running Benchmarks & Server on Windows
Double-click or run any of the utility batch files in your terminal:

1. **Start the REST API Server (Port 8080):**
   ```cmd
   run_vectordbserver.bat
   ```

2. **Run Linear Search (1M vectors):**
   ```cmd
   run_linear_search.bat
   ```

3. **Run Greedy Graph Search:**
   ```cmd
   run_greedy_graph_search.bat
   ```

4. **Run Performance Comparison:**
   ```cmd
   run_comparison.bat
   ```

### Testing the REST API Server via Python
While `VectorDBServer.exe` is running, execute the Python test scripts to benchmark network and application latency:

1. **Test Insertion API (`/insert`):**
   ```bash
   python test_insert.py
   ```
   * **C++ DB Insertion Latency:** **~2.62 ms** (includes priority-queue graph traversal and bidirectional link construction)
   * **Python Request Elapsed Time:** **~5.26 ms**
   * **Network Round-Trip Time (RTT):** **~6.92 ms**

2. **Test Search API (`/search`):**
   ```bash
   python test_search.py
   ```
   * **C++ DB Search Latency (Greedy ANN):** **~0.017 ms** (equivalent to **17 microseconds**!)
   * **Python Request Elapsed Time:** **~1.44 ms**
   * **Network Round-Trip Time (RTT):** **~2.99 ms**

### Manual Compilation
If you are on Linux or macOS, compile and run the server using:
```bash
g++ -std=c++17 -O3 VectorDBServer.cpp -o VectorDBServer -lpthread
./VectorDBServer
```
